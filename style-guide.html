00

Principles

Four rules that every onboarding screen must pass. If a screen breaks one, redesign the screen, not the rule.

One question, one screen

Never stack questions. The question is the hero: set in display type at the top, options below, primary action pinned at the bottom. Chat scroll is gone; each screen is a composed moment.

Tap first, type never*

Every answer should be reachable in one tap. Free-text only where identity demands it (name). Selecting an option auto-advances after 350 ms. No redundant "Next" tap for single-selects.

Indigo is touch, gold is treasure

Indigo marks selections, focus and links. The primary button is white, the single brightest element on a dark screen. Gold appears only when the learner gains something: progress, streaks, celebration. Gold on a button is a system violation.

Progress is felt, not read

The gold progress bar animates on every answer, paired with a micro-label ("Cool name!"). The learner should feel forward motion within 200 ms of every tap.

03

Iconography

Exploration, not yet locked. Emoji got us here, but they render differently on every phone and add color noise to the dark UI. Four directions below, same five glyphs each. Tap a direction card to preview it on live option cards underneath.

Applied to the option card (switches with the direction above)

Grid & usage rules (apply to whichever direction wins)

Grid: 24px viewBox, 1.75px stroke, round caps and joins, 1.5px minimum inner gap. Sizes: 20px inline, 24px in cards, 22px inside a 44px tile.

Color: mono directions rest at text-mid and select to indigo-400. The tinted direction uses a fixed 5-hue palette (tint-gold, green, blue, purple, red) muted to uniform luminance; tints are decorative and never change with state.

Flags stay emoji. The native-language question keeps 🇮🇳 🇮🇩 🇻🇳 flags regardless of direction; mono flags are unreadable at 24px and emoji flags are a familiar pattern there.

One icon per option, always leading. No trailing icons, no icon-only answers; the label carries meaning, the icon speeds scanning.

05

Core components

Everything below is live. Tap it. These classes ship in tokens.css and are the only building blocks screens may use.

Buttons

Primary is white, the brightest element on screen, so the main action always wins the eye. Full-width, pinned to the bottom safe area, disabled until the screen is answerable. Skip is quiet text: visible, never competing.

Text input

What should Sarah call you?
Letters only, please

56px tall, indigo focus ring, indigo caret. Errors go red on the border + a 13px helper line, never a toast.

Option card · single-select (tap one)

Anatomy: 22px emoji · 16px Inter Display 500 label · 22px radio that springs to an indigo check.

Selection = indigo tint fill + indigo-500 border + soft outer glow. On single-select, auto-advance 350ms after the check lands.

Min height 60px, comfortably thumbable. Cards press to 0.98 scale on tap.

Chips · multi-select (tap several)

Multi-select never auto-advances; the pinned Continue button confirms. Cap visible chips at 8; selected count can echo in the CTA ("Continue · 2 picked").

Progress · the gold system

Cool name!

One continuous bar for the whole journey, and it only ever moves forward. Fill animates 450ms ease-out with a gold glow; the eyebrow micro-label celebrates each answer.

07

Motion

Motion is the timing system for everything that moves in the flow: the press of a button, an option card filling in, one screen sliding to the next, the progress bar advancing, the celebration popping. Each row below is a speed, and the "used for" column says which moments get it. Two easings only: ease-out for everything functional, spring for moments of delight. Click a row to preview its timing.

DO
  • Stagger option cards in by 40ms each on screen entry
  • Slide screens horizontally (forward = left) at dur-slow
  • Fire a confetti burst with every celebration, no exceptions
  • Respect prefers-reduced-motion: collapse to fades, drop confetti
DON'T
  • Animate anything longer than 600ms except celebrations
  • Use spring easing on functional UI (inputs, screens)
  • Move more than one thing per moment of attention
